# Контракт терминального Ocean 1.0

Команды комнат, разбора, doctor, backup, restore и install реализованы в M1–M5. Для запуска существующего демо и TUI используй команды в [README](../../README.md). Здесь `ocean` обозначает установленный исполняемый файл кандидата.

## Один профиль и два способа управления

Профиль по умолчанию находится в `$XDG_STATE_HOME/ocean` (при отсутствии переменной — `~/.local/state/ocean`). В нём конфигурация и `runtime.sqlite`. Общий флаг `--profile <абсолютный каталог>` выбирает иной профиль. `ocean init --workspace <каталог>` фиксирует канонический путь к существующему workspace. Повтор с тем же путём возвращает профиль, попытка перепривязать непустую историю к другому пути отклоняется. Явный выбор чужой или несовместимой базы даёт ошибку. Унаследованные `RUNNE_DB` и `RUNNE_MODE` относятся к прежнему интерфейсу. Конфликт этих настроек с выбранным Ocean-профилем требует явного выбора и не разрешается молча.

В интерактивном режиме `ocean tui` держит владельца базы до выхода. Действия выбора бота, группы, просмотра истории, отправки, остановки вызываются внутри TUI; doctor запускается отдельной CLI-командой, при занятом профиле данные базы недоступны. В пакетном режиме каждая команда открывает и закрывает профиль. `send` ожидает исход хода, Ctrl+C относится к этому ходу. Из второго процесса при занятом профиле возвращается `owner_busy`. Для ACP используется прежний протокол по stdio и отдельный сеанс владения. Локальные прикладные команды используются обоими терминальными интерфейсами.

## Рабочие команды

| Целевой вызов                                                                              | Результат                                                                                                                                    |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `ocean bot add --handle dev --name Разработчик --role "Правит код"`                        | Возвращает botId. Адрес уникален внутри профиля, ASCII в нижнем регистре по шаблону [a-z][a-z0-9_-]{0,31}. Имя и роль могут быть на русском. |
| `ocean bot list`                                                                           | ID, адрес и имя доступных ботов. В 1.0 изменение состава или профиля через редактирование файлов не поддерживается.                          |
| `ocean room direct --bot dev`                                                              | Создаёт или возвращает единственный roomId личного диалога для workspace и этого бота.                                                       |
| `ocean room group --name Команда --bot dev --bot review`                                   | Создаёт комнату с владельцем и минимум двумя различными известными ботами. Состав фиксирован на момент создания.                             |
| `ocean room list`, `ocean room members <roomId>`                                           | Список комнат своего профиля и состав выбранной комнаты.                                                                                     |
| `ocean send <roomId> --text "Проверь функцию" --request-id <id>`                           | В прямом чате запускает его бота. В группе без адреса сохраняет реплику без вызова модели.                                                   |
| `ocean send <roomId> --to review --text "Проверь решение" --request-id <id>`               | Назначает ход конкретному участнику, возвращает messageId, turnId и taskRunId.                                                               |
| `ocean history <roomId> --after <seq> --limit 50`                                          | Сообщения в порядке seq, только позиции строго больше курсора. По умолчанию 50, максимум 200.                                                |
| `ocean run show <taskRunId>`, `ocean run review <taskRunId>`                               | Статус и отдельные факты о результате модели, инструментах и отмене; review показывает доступный способ восстановления.                      |
| `ocean run acknowledge <taskRunId> --text-only --review-version <token> --reason "..."`    | Действие владельца в живом TTY. Записывает решение о продолжении разговора с ограничениями из [протокола восстановления](persistence.md).    |
| `ocean backup --to /new/snapshot`, `ocean restore --from /snapshot --profile /new/profile` | Согласованная проверенная копия и восстановление в новый ограниченный профиль.                                                               |
| `ocean install --archive /file --sha256 HASH --prefix /prefix`                             | Установка, обновление или откат бинарника с проверкой хеша.                                                                                  |
| `ocean doctor`, `ocean --version`                                                          | Проверяют профиль и версию. Формат диагностики и порядок действий описаны в [руководстве оператора](operations.md).                          |

В TUI адресат выбирается из состава комнаты. При текстовом вводе разрешён один начальный токен `@handle`, совпадающий с выбранным адресатом. Два начальных адреса, конфликт с `--to` или адрес чужого бота дают ошибку до записи. Упоминание внутри цитаты или обычного предложения остаётся текстом. В прямом чате явный адрес обязан совпасть с владельцем диалога. Модель не парсит собственный ответ как команду маршрутизации.

## Результаты и повторы

Общий `--json` возвращает один объект версии 1 в stdout. Прогресс и пояснения идут в stderr. Идентификаторы считаются непрозрачными строками. Пример после успешного хода:

```json
{
  "version": 1,
  "ok": true,
  "data": {
    "roomId": "r1",
    "messageId": "m1",
    "turnId": "t1",
    "taskRunId": "tr_example",
    "status": "succeeded",
    "replyMessageId": "m2"
  }
}
```

Ошибка имеет форму `{version:1,ok:false,error:{code,message},data:{...}}`. После принятия запроса data содержит сохранённые идентификаторы даже при ошибке модели. Для реплики без исполнения — статус `recorded` и null в полях запуска. При повторе принятого send возвращаются прежние идентификаторы и текущий статус, обращение к провайдеру не выполняется. Изменённый адресат или текст с тем же ключом дают `request_conflict`. Все создающие команды принимают `--request-id`; клиент генерирует ключ до отправки, при пакетном повторе передаёт прежний. Занятость отклоняет новый запрос до записи, проверка существующей квитанции предшествует проверке занятости.

| Код процесса | Примеры стабильных кодов                                 | Действие                                 |
| ------------ | -------------------------------------------------------- | ---------------------------------------- |
| 0            | recorded, succeeded                                      | Показать запись или ответ                |
| 2            | invalid_input, unknown_bot, not_member, request_conflict | Исправить запрос                         |
| 3            | owner_busy, room_busy                                    | Дождаться владельца или активного хода   |
| 4            | permission_denied, recovery_required, context_limit      | Показать причину и предложенное действие |
| 1            | storage_error, provider_error, incompatible_schema       | Показать безопасную диагностику          |

Коды относятся к новому CLI Ocean. Существующие ACP ответы сохраняют формат. В группах по умолчанию работает один активный ход. У других комнат сохраняется изоляция истории. Инструментальные ограничения могут действовать шире одной комнаты.

Команда send возвращает код 4 и статус cancelling/reconciling, если прекращение работы ещё не подтверждено; идентификатор запуска остаётся доступным. Для этих случаев exit 0 зарезервирован для успешного запроса состояния, а не для успешного выполнения задачи. Ошибка недоступности модели до передачи запроса освобождает комнату по правилам хранения. Потеря связи после возможной передачи переводит ход на разбор.

## Данные для модели

Бот получает системную роль из своего профиля и опубликованную историю комнаты до позиции исходного сообщения включительно. Чужие сообщения помечаются автором и передаются как входные данные. Ответ самого бота восстанавливается с ролью ассистента. Потоковые фрагменты, служебные ошибки, приватные сведения об инструментах и скрытые рассуждения в общий контекст не входят. Инструментальные сообщения текущей попытки доступны её движку.

Предел 1.0 — 16 КиБ UTF-8 на пользовательскую реплику, пустой текст отклоняется. История хранится целиком. Перед вызовом проверяется ограничение запроса выбранной модели с резервом под ответ по профилю адаптера. Если историю нельзя уместить или оценить в заданном лимите, вернуть `context_limit` до отправки; пользователь может открыть новую группу или явно начать новую тему в отдельном профиле. Молчаливое усечение и перенос приватной истории недопустимы.

После restore разрешены просмотр и отдельный подтверждённый текстовый send через --text-only; TUI и прежние task/ACP-режимы заблокированы. Подробности и ограничения — в [руководстве оператора](operations.md).
