# Модель общения Ocean v1

Ниже описано целевое поведение v1. В M1 реализованы профили, личные комнаты и пользовательская история через [прикладной API](../integration/conversations.md). В M2 личные комнаты доступны через CLI и tui --room, ответы ботов и контекст переживают перезапуск. Прежний tui без комнаты сохраняет режим базового runtime. Для v1 один локальный пользователь работает в одном workspace через один процесс, владеющий постоянной SQLite-базой.

## Что хранится

| Сущность | Назначение                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bot      | Постоянный идентификатор, уникальный короткий адрес, отображаемое имя, роль, настройки модели. Права на инструменты проверяются при исполнении.         |
| Room     | Идентификатор, тип direct/group, workspace и состав участников. Повторное открытие личного диалога с ботом в том же workspace возвращает ту же комнату. |
| Message  | Идентификатор, комната, порядковая позиция, автор, текст, адресат при наличии. Ответ ссылается на исходное сообщение и TaskRun.                         |
| Turn     | Назначение одного входящего сообщения одному боту. Фиксирует версию профиля или его снимок, границу прочитанной истории и идентификатор TaskRun.        |
| TaskRun  | Унаследованный агрегат исполнения. Хранит состояние запуска, попытки, бюджет, отмену и исход инструментальных действий.                                 |

Один бот участвует в нескольких комнатах под одной идентичностью. Переписка и контекст разделены по комнатам. Добавление бота в группу требует явного действия пользователя. Для первого выпуска состав задаётся при создании группы, всем её участникам доступна общая история с момента создания. Пересылка личной переписки в группу потребует отдельного действия пользователя.

## Кто отвечает

- В личном чате сообщение пользователя адресуется единственному боту.
- В группе пользователь выбирает одного бота из состава через явное упоминание или выбор адресата в CLI. Сообщение без адресата остаётся в общей истории. Неизвестный адрес или несколько адресатов возвращают ошибку до запуска.
- Ответ бота виден всей комнате. Текст ответа, в том числе упоминание другого бота, сам по себе не запускает следующий ход и не даёт разрешения на инструмент. Следующего участника вызывает пользователь.
- В первой версии в комнате исполняется один ход за раз. При занятой комнате новый адресованный запрос получает статус «занято» до записи сообщения. Отмена относится к конкретному запуску. Неопределённое исполнение видно в комнате и блокирует следующие запуски в ней до решения по [протоколу восстановления](persistence.md). Владелец может открыть новые текстовые ходы, оставив исход старого действия неопределённым и сохранив запрет на инструменты.

## Что получает модель

Для хода runtime выбирает профиль адресата и опубликованные сообщения только этой комнаты до зафиксированной позиции включительно. Текст других ботов передаётся как авторское сообщение с указанием автора. Роли и полномочия определяет runtime. В публичную историю попадает итоговый ответ, а не скрытые рассуждения, секреты или сырой вывод команд. Внутренние данные вызова инструмента доступны владельцу соответствующей попытки в пределах существующих ограничений. Потоковые фрагменты служат для отображения. При обрыве незаконченный поток не становится финальным ответом.

## Повтор и перезапуск

При приёме клиент передаёт стабильный идентификатор команды. Runtime атомарно сохраняет входящее сообщение и назначение с заранее выделенным TaskRun ID. Совпадающий повтор возвращает исходную квитанцию. Повтор с изменённым содержимым отклоняется. Запуск возможен после фиксации. История ответа и связанный результат получают однозначную связь с запуском, чтобы сбой между завершением и публикацией не породил второй ответ. Целевой протокол фиксирует полный подготовленный результат до завершения TaskRun и допускает повтор только локальной публикации. См. [хранилище и восстановление](persistence.md).

После перезапуска Ocean восстанавливает историю, участников и состояние запуска. Опубликованный ответ доступен сразу. Незавершённый ход с возможным внешним действием показывается с причиной и идентификатором запуска. Восстановление переписки не отправляет новый запрос модели и не повторяет команду инструмента. Выход процесса с кодом 0 сам по себе не подтверждает остановку потомков.

Домен задаёт правила адресации, application координирует ход, адаптер SQLite хранит факты, CLI/TUI показывает результат. Новый API комнат начинается с типизированных прикладных команд и запросов. Внешний ACP-контракт развивается отдельно, когда появится проверенный клиентский сценарий.
