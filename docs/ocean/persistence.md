# Данные и восстановление Ocean

Рабочая схема M4 имеет версию 5. Обновление поддерживает версии 1–4. События TaskRun сохраняют исходный формат. Перед обновлением реального профиля владелец останавливает его и делает проверенную резервную копию. Процедуры поставки и восстановления из копии относятся к [эксплуатации](operations.md).

## Авторитетные записи

| Таблица                                  | Что хранится и проверяется                                                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| ocean_workspace                          | Один workspace на профиль, его ID и канонический root                                                                                        |
| ocean_bots                               | Неизменяемый профиль, уникальный handle внутри workspace, настройки провайдера и модели                                                      |
| ocean_rooms, ocean_members               | Личная или групповая комната, состав из того же workspace. Единственная личная комната для пары workspace/бот                                |
| ocean_messages                           | Порядок seq внутри комнаты, автор и адресат, текст и время. Ответ бота связан с turn_id и публикуется один раз                               |
| ocean_chat_turns                         | ID задачи, входящее сообщение, граница прочитанной истории, снимок профиля, фаза исполнения, полный подготовленный ответ и его версия задачи |
| ocean_receipts                           | Привязка request ID к полному запросу и сохранённый результат. Изменённый повтор получает конфликт                                           |
| ocean_reviews                            | Решение владельца, причина, просмотренная версия, время, ссылка на ход и записанное уведомление. Один разбор на прерванный ход               |
| ocean_room_policies                      | Постоянный режим text_only со ссылкой на принятое решение                                                                                    |
| events, command_receipts, checkpoints    | Доменные события и квитанции TaskRun                                                                                                         |
| tool_invocations_v1, tool_invocations_v2 | Неопределённые и завершённые действия, сохраняющие запрет повторного исполнения                                                              |

Состояние хода хранится в JSON payload вместе с индексируемыми идентификаторами и статусом. Полный подготовленный ответ — часть этой записи. Отдельная таблица ocean_final_results не требуется. continuationReviewId в payload соответствует review_id в строке. Расхождение отклоняется при чтении.

## Один адресованный ход

1. В транзакции проверить квитанцию до проверки занятости, разрешить адресата, зафиксировать входящее сообщение и ход с зарезервированным TaskRun ID. Историю для модели ограничить комнатой и прочитанной позицией. Групповая реплика без адресата сохраняется с квитанцией без TaskRun.
2. После commit создать TaskRun идемпотентной командой. До обращения к провайдеру зафиксировать dispatching. Повтор входящего request ID только читает сохранённый исход.
3. Зафиксировать usage через TaskRunService. Полный валидный финальный текст и ожидаемую версию задачи записать в фазе prepared до Complete.
4. После успешного Complete записать ответ в историю и completed в одной транзакции. Уникальные ссылки и номер seq исключают повторную публикацию.
5. При старте под эксклюзивным владельцем сначала завершить только локальные операции для prepared, затем проводить общую reconciliation. Сокращённый summary задачи никогда не заменяет текст ответа.

## Прерывание

| Факт после сбоя                                        | Поведение восстановления                                                                                          |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| accepted, разрешение dispatch ещё не выдавалось        | Отметить ход failed и показать сохранённый пользовательский ввод. Новую работу запускает отдельная явная отправка |
| prepared и подходящая running-версия задачи            | Локально завершить TaskRun и опубликовать сохранённый ответ                                                       |
| prepared и succeeded                                   | Локально опубликовать сохранённый ответ один раз                                                                  |
| dispatching или несовместимое состояние prepared       | Сохранить uncertain, удержать комнату для разбора и сохранить возможный расход                                    |
| started в журнале инструментов                         | Перевести в uncertain и сохранить глобальную блокировку новых claims                                              |
| cancelling без положительного свидетельства завершения | Оставить отмену неподтверждённой                                                                                  |

Сбой самого хранилища прекращает дальнейшее внешнее исполнение. Если квитанция могла сохраниться, клиент повторяет запрос с тем же ключом. Новый ключ нельзя генерировать как автоматический повтор потерянного ответа.

## Решение владельца

[CLI и TUI разбора](../integration/recovery.md) позволяют просмотреть состояние и подтвердить новое текстовое продолжение. Разбор возможен только для uncertain без предыдущего решения. Активный dispatch подтверждать нельзя. В интерфейсе нужно сначала увидеть состояние, затем явно согласиться с неизвестным прошлым исходом и возможной новой оплатой.

Квитанция решения привязана к workspace, задаче, причине и точной версии просмотра. После подтверждения в одной транзакции повторно проверяются committed head задачи, фаза хода, режим комнаты и полный набор незавершённых claims. Синхронные методы официальных адаптеров читают тот же критический участок. Изменение состояния возвращает review_conflict.

Транзакция сохраняет уведомление от имени владельца, аудит, режим text_only, continuationReviewId и квитанцию. Причина остаётся в аудите. Уведомление содержит только фиксированное описание решения и ID прежней задачи. Индекс исключает рассмотренный uncertain из удерживающих комнату записей. Исход TaskRun и журнал инструментов остаются прежними. Следующая явная реплика создаёт новый запуск.

Позднее обновление не может удалить ссылку на разбор и вернуть старое удержание комнаты. Старый ответ после разбора не публикуется. Режим комнат всегда передаёт модели пустую инструментальную поверхность. Подтверждение не выдаёт полномочий legacy-инструментам и не удостоверяет остановку дерева процессов.

## Миграция

Вход выполняет BEGIN IMMEDIATE и проверяет владельца до изменений схемы. Живой или непроверяемый владелец, новая неизвестная версия и ошибка целостности приводят к отказу. Последовательные преобразования 1→2→3→4→5 выполняются в одной транзакции, версия меняется последней.

Для перестройки родительских таблиц на шаге 3→4 SQLite foreign_keys временно выключается только на соединении мигратора. foreign_key_check обязателен до commit, исходная настройка восстанавливается в finally и при ошибке. M4 добавляет аудит и политику, сохраняя старые строки и неопределённые claims. Прежним ходам назначается пустой review_id, поэтому все прежние удержания сохраняются.

Проверки миграции сравнивают старые записи и восстанавливают схему после искусственного сбоя. Реальные kill-тесты проверяют границы принятия, dispatch, подготовки ответа и публикации. Восстановление старого snapshot не доказывает отсутствие действий после него и требует отдельного эксплуатационного разбора.
