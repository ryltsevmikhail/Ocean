# Эксплуатация Ocean: M5

M5 реализован для Linux x86_64, локальной файловой системы и Node 26. Архив фиксирует точную версию Node; launcher требует именно её. Проверки исходников и тестового установленного экземпляра выполняются на БигПК. Это ещё не выпуск 1.0: живой DeepSeek и полная матрица RC проверяются отдельно.

## Сборка и установка

В чистом зафиксированном checkout с Node 26 и pnpm 12.16.1:

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm format:check
pnpm package:release 0.1.0-m5 /absolute/output
```

Команда повторяет build и отказывается упаковывать грязное дерево. Результат: `ocean-0.1.0-m5-linux-x64.tar.gz`, отдельный SHA-256 и автономный `ocean-install.mjs`. Манифест внутри архива содержит версию, Git SHA, точный Node, платформу, SHA-256 lockfile и перечень файлов с хешами и правами. pnpm закреплён в исходном package.json; не требуется при запуске установленной программы.

В архив входят собранные ESM-пакеты с runtime-зависимостями, launcher, установщик обновлений, README, LICENSE, NOTICE, LICENSES и документация. Workspace-зависимости превращаются в обычные каталоги node_modules; символических ссылок, исходников, кеша сборки, профилей и ключей нет. Неизвестная внешняя runtime-зависимость блокирует упаковку.

Получить установщик и контрольную сумму по доверенному каналу. Сумма рядом с архивом сама по себе не доказывает его происхождение. Установка не требует pnpm или исходного репозитория:

```sh
node /absolute/output/ocean-install.mjs \
  --archive /absolute/output/ocean-0.1.0-m5-linux-x64.tar.gz \
  --sha256 TRUSTED_SHA256 --prefix /home/user/.local
/home/user/.local/bin/ocean --version
```

Установщик проверяет сумму до распаковки. Принимаются только обычные файлы ustar: абсолютные пути, переходы через родителя, ссылки, устройства, повторные имена, повреждённые заголовки и несовпадение манифеста отклоняются. Размер распакованного архива ограничен 256 МиБ. Prefix должен быть абсолютным, без символических ссылок в пути.

Версии сохраняются в `PREFIX/lib/ocean/releases/VERSION`, `current` переключается атомарной заменой ссылки; `PREFIX/bin/ocean` указывает на установленный launcher. Запись файлов и каталогов синхронизируется перед переключением. Новые файлы программы получают права из манифеста независимо от umask. Для совместимости с ранними установщиками принимаются также неизменённые файлы с правами 0600 вместо 0644 и 0700 вместо 0755; более широкие права отклоняются. После проверки всех файлов безопасные прежние права нормализуются к манифесту, чтобы последующее обновление старым установщиком тоже работало. Точная повторная установка допустима; изменённая версия или чужой launcher не перезаписываются. Каталоги предыдущих версий сохраняются. Профиль при установке не открывается и не мигрирует.

## Профиль и команды

```sh
ocean init --workspace /absolute/workspace --profile /absolute/profile
ocean doctor --profile /absolute/profile --json
ocean bot add --handle dev --name Developer --role "Develops" --profile /absolute/profile
ocean bot add --handle review --name Reviewer --role "Reviews" --profile /absolute/profile
ocean room direct --bot dev --profile /absolute/profile
ocean room group --name Team --bot dev --bot review --profile /absolute/profile
```

По умолчанию используется `$XDG_STATE_HOME/ocean` или `~/.local/state/ocean`. Профиль принадлежит одному локальному пользователю и одному процессу. Каталог создаётся с 0700, SQLite — с 0600; существующие файлы с доступом группы/остальных или ссылки отклоняются. У старого закрытого тестового профиля владелец может явно исправить права через chmod 700 каталога и chmod 600 SQLite/WAL/SHM. Ocean не меняет небезопасные существующие права молча.

Конфигурация workspace и ботов находится в SQLite. `DEEPSEEK_API_KEY` поступает только из окружения процесса, не записывается в профиль, архив или snapshot. `RUNNE_DB` и `RUNNE_MODE` нельзя совмещать с командами Ocean-профиля.

## Диагностика

`ocean doctor --json` выполняет только локальное чтение. Он не вызывает модель, не мигрирует базу, не проводит recovery и не забирает владение. Возвращает CLI/Node/платформу, результат проверки прав, признак и состояние восстановления (ready/incomplete), логический флаг наличия ключа, состояние базы и время последней зарегистрированной проверенной копии. `lastError: unavailable` означает, что сохраняемого журнала эксплуатационных ошибок пока нет.

При свободном совместимом профиле проверяются integrity_check и foreign_key_check, сообщаются схема, число комнат/сообщений, последняя seq каждой комнаты, незавершённые TaskRun, удерживаемые комнаты и незакрытые инструментальные claims. Тексты, аргументы инструментов, ключ и трассировки в сводку не попадают.

При занятом профиле результат `database.status=owner_busy`, остальные данные базы недоступны. Дождаться выхода владельца; не удалять запись владельца вручную. При неподдерживаемой схеме — `unsupported_schema`, при повреждении — `invalid_database`. Код 0 означает успешную локальную проверку; 3 — нужна проверка оператором (включая отсутствующий/занятый профиль или другую платформу). Наличие ключа не доказывает доступность провайдера. Команды диагностики внутри активного TUI пока нет.

При ошибке записи остановить новые запросы, сохранить закрытый профиль, проверить свободное место и целостность копии. При неизвестном эффекте использовать [разбор M4](../integration/recovery.md). Поддержка реальной остановки дерева процессов не добавлена в M5.

## Резервное копирование

Остановить TUI/другого владельца. Каталог назначения должен быть новым, его родитель — существующим доверенным каталогом.

```sh
ocean backup --profile /absolute/profile --to /absolute/backups/snapshot-001 --json
```

Backup требует существующую совместимую базу схемы 5, 6, 10, 11 или 12 и приватные файлы. Он не мигрирует и не восстанавливает исходник. Общая запись владельца исключает параллельный Ocean runtime во время снимка. SQLite backup API включает данные WAL; копирование одного открытого sqlite-файла вручную не заменяет эту операцию.

Новые копии используют формат 2: `runtime.sqlite` с очищенной записью владельца, `snapshot.json` и приватный `assets/`. Старые копии формата 1 читаются с прежними ограничениями. Манифест фиксирует время, CLI/Node, размер/хеш базы, схему, позиции комнат и счётчики. Снимок проверяется на целостность и внешние ключи; сводка сверяется с исходником. Истории, квитанции, полные подготовленные ответы, audit и ограничения комнат, включая неизвестные tool claims, сохраняются. Полный снимок включает выбранные управляемые worktree/Git, recovery, зарегистрированные зависимости, pnpm, workspace packages и связанные Desktop assets. Исходные checkout не превращаются в рабочие копии восстановления; ключи не копируются. Точные поддерживаемые и отклоняемые состояния описаны в [контракте формата 2](../integration/profile-backup.md).

Каталог копии — 0700, файлы — 0600. До копирования создаётся durable `.incomplete`. Маркер удаляется только после независимой проверки базы и полного графа; наличие маркера всегда запрещает использование. Существующий каталог не перезаписывается. Ошибка формата 2 оставляет неполный каталог как свидетельство; исходники не очищаются. После успешного снимка Ocean по возможности записывает информационный `last-backup.json`; doctor не утверждает, что эта копия до сих пор существует или не изменена.

Снимок содержит конфиденциальную переписку. Хранить минимум две проверенные версии, одну на другом доверенном носителе. Делать копию перед обновлением и после рабочего дня с новыми сообщениями. Цель RPO — один рабочий день; RTO — 30 минут. Эти цели требуют измерений на данных оператора при RC, быстрый тестовый прогон их не квалифицирует.

## Восстановление

```sh
ocean restore --from /absolute/backups/snapshot-001 --profile /absolute/new-profile --json
ocean doctor --profile /absolute/new-profile --json
ocean room list --profile /absolute/new-profile
ocean history ROOM_ID --profile /absolute/new-profile
```

Восстановление допускается только в новый каталог. Оно не изменяет копию, не перезаписывает существующий профиль и не выполняет внешнюю работу. Проверяет права и отсутствие ссылок, формат, размер, SHA-256 скопированной базы, integrity_check, внешние ключи и полное совпадение сводки/позиций. Изменённый snapshot отклоняется. Хеш защищает от повреждения; копия должна происходить из доверенного источника.

Сразу создаётся `restore-guard.json` в состоянии restoring. Только после всех проверок атомарно фиксируется ready. Неполный профиль не допускается к работе даже с ready-guard, если остался `.incomplete`. Ошибка формата 2 сохраняет неполный карантин; исторический путь формата 1 сохраняет прежнюю обработку ошибок. Все assets формата 2 размещаются в приватном карантине, а исходные абсолютные пути остаются инертными. Оригинальный workspace не изменяется; автоматический rebind и восстановление права исполнения не выполняются.

Снимок мог предшествовать реальному действию или оплате. Поэтому восстановленный профиль ограничен просмотром истории, списков и run review; решение M4 можно подтвердить отдельно. Обычный send, изменение ботов/комнат, TUI, прежние task/ACP-режимы с этой базой заблокированы. Ограничение не снимается автоматически. После сверки утраченного интервала владелец может явно разрешить один новый текстовый ход:

```sh
ocean send ROOM_ID --text "New question" --text-only \
  --request-id NEW_ID --profile /absolute/new-profile
```

Каждый такой вызов требует подтверждения `y` в живом TTY; перенаправленный stdin не считается согласием. Предупреждение говорит о возможной прежней оплате. Новый ход получает сохранённый контекст, инструменты не передаются. Старые запросы не повторяются; неопределённый ход по-прежнему требует разбора M4. Возможности вернуть инструменты или TUI после restore в M5 нет.

## Обновление и откат

1. Завершить активные процессы и сделать проверенную копию старой версией. Сохранить текущий архив, сумму и сведения о snapshot.
2. На копии пройти restore/doctor новым кандидатом, проверить историю, позиции и ограничения. Не использовать реальные внешние эффекты для пробной миграции.
3. Установить новый архив командой `ocean install --archive /new.tar.gz --sha256 HASH --prefix /home/user/.local`. Установленный CLI содержит собственный установщик. Переключение программы не касается профиля.
4. Запустить doctor, затем открыть нужную комнату. Первая обычная команда применяет поддерживаемую миграцию через штатный runtime. M5 сохраняет схему 5; собственного изменения схемы нет.
5. Для отката программы установить прежний архив той же командой. Обе версии остаются на диске. Старую программу нельзя открывать на несовместимой новой схеме.
6. Если нужен откат данных — сохранить оба состояния и восстановить проверенную копию в новый профиль. Учитывать потерю новых записей и неизвестные эффекты; ограничения restore сохраняются. Откат бинарника не отменяет оплату или изменения workspace.

## Проверки и выпуск

Автотесты покрывают WAL, занятость владельца, неизменность неизвестных claims, повреждённый snapshot, приватность, запрет эффектов после restore, согласованность контекста, установку, повтор, обновление и откат без исходников, недоверенные пути/ссылки/хеши и сбой синхронизации staging. Временные профили и сценарный провайдер не требуют реального ключа.

Для RC зафиксировать чистый Git SHA, lockfile и архив/контрольную сумму, Node/ОС, исходную/конечную схему. На установленном экземпляре пройти Q01–Q12 из [матрицы](qualification.md), живую переписку DeepSeek, ручное подтверждение в TTY, backup/restore и откат с измерением времени и фактических потерь. Хранить свидетельства вне публичного checkout, без ключей и реальной переписки. Успех этих разработческих проверок не заменяет решение владельца о выпуске 1.0.

## Кандидат 1.1: Linux prerequisites и границы проверки

Разделы M5 выше описывают исторический эксплуатационный контракт. Текущая квалификация 1.1 проводится отдельно на Omarchy Linux x86_64; она не переносит результаты БигПК, Desktop GUI или живого DeepSeek на новый установленный архив автоматически. CLI-архив не содержит Electron-приложение Desktop.

Для установленного CLI нужен Linux x86_64 и **точный patch Node из manifest.json**. Установщик принимает манифест Node 26; launcher дополнительно сверяет полный `process.version` и отказывается запускать несовместимый архив. pnpm 12.16.1 нужен для воспроизводимой сборки и зарегистрированных pnpm-пресетов, но не для обычного запуска установленного CLI.

Shared runtime использует `/usr/bin/python3` с `-I -S`, Linux Unix sockets, `/proc/self/fd` и `SO_PEERCRED` для проверки endpoint перед публикацией. Отсутствующий или несовместимый Python блокирует публикацию с `endpoint_verification_unavailable`. Нужны приватные профиль и runtime directory; длинный путь Unix socket может потребовать короткого приватного XDG_RUNTIME_DIR. `doctor --static` проверяет конфигурацию и права, но **не квалифицирует Python, endpoint или sandbox**. Успешный doctor не заменяет фактический `runtime start` и проверку worker.

Регистрация и подготовка coding task требуют Git. Coding worker требует `/usr/bin/bwrap`, `/usr/bin/systemd-run`, `/usr/bin/systemctl`, доступный systemd user manager и cgroup v2. Контроллер worker обращается к user bus через `/run/user/UID`, даже если клиент использует отдельный XDG_RUNTIME_DIR. До запуска проекта выполняется реальный isolation canary. Если containment недоступен, инструменты отказывают; автоматического запуска без sandbox нет. Подтверждение остановки требует наблюдения пустого cgroup или проверенного удаления его каталога, а не только выхода родителя.

Действующие ограничения worker: 60 секунд, 32 КиБ сохранённого вывода, 2 ГиБ памяти и 256 процессов/потоков. Проверка и снимки зависимостей на стороне host добавляют время к этим 60 секундам. Зависимости устанавливают заранее по frozen lockfile; worker получает только перечисленные read-only mounts, пустой HOME и отключённую сеть. Для pnpm 12 пресетов можно явно зарегистрировать `pnpm --config.verifyDepsBeforeRun=false run SCRIPT`, чтобы pnpm не пытался переустановить read-only node_modules перед скриптом. Команда и флаг входят в точный owner preview. Прохождение небольшого тестового проекта не доказывает, что полный набор тестов Ocean укладывается в те же ограничения.

Для полного source-набора Ocean при read-only зависимостях зарегистрированы три отдельных пресета: `pnpm --config.verifyDepsBeforeRun=false run test --configLoader native --no-cache --no-color --maxWorkers 5 --shard=N/3 --reporter=default`, где N равен 1, 2 и 3. Каждый пресет требует собственного точного подтверждения владельца. Native config loader исключает запись Vite в `node_modules/.vite-temp`; три части сохраняют прежние лимиты worker. Квалификация требует сравнить фактически завершённые файлы с независимым полным списком и partition алгоритмом закреплённой версии Vitest: части должны быть непересекающимися и покрывать весь список. Сам `vitest list --shard` не доказывает это покрытие. Сохранить все исходы, суммы тестов, вывод, cleanup и неизменность source/dependencies; не выдавать timeout полного одиночного запуска за успех частей.

Тесты, которым нужен собственный native worker, выполняют отдельно через `OCEAN_SANDBOX_NATIVE=1` вне уже изолированного worker. Пропуск такого теста в source-наборе не подтверждает его native-поведение. Доступ к host user bus внутрь worker для вложенного запуска не предоставляется. Полный source-набор и выбранные native-контракты — отдельные свидетельства; GUI, живой провайдер и решение о выпуске остаются самостоятельными воротами.

После format-2 restore assets остаются в карантине. Для нового execution epoch предусмотрены установленный `ocean runtime restore` и команды `ocean rebind inspect|preview|confirm|result --config /private/config.json --profile /restored/profile`. Inspect-конфигурация содержит workspaceId, roomId, requestId, taskId, выбранный чистый projectRoot и точную policy; возвращённый `selection` используется следующими командами. Confirm требует живой TTY и показывает точный digest. Redirected stdin не даёт разрешения. Старые решения остаются историческими записями и не создают новый executable grant.

Проверка полного графа зависимостей может занимать более пяти секунд. Restore inspection, preview, result и проверка owner decision используют ограниченный RPC budget 30 секунд. Это не меняет срок действия approval, лимиты worker и recovery-политику. Timeout не означает ни отказ, ни отмену уже подтверждённого действия: нужно прочитать `rebind result` для того же selection и сохранить evidence; автоматически повторять неизвестный эффект нельзя.
