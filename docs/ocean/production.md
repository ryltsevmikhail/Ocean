# Ocean 1.0. План до промышленного выпуска

**Текущие приоритеты (2026-11-04):** runtime/server, локальный движок и
графический чат ботов — приоритет 1; графический клиент проектов — приоритет 2;
развитие двух TUI — позднее. Облачные API, локальные модели и смешанные команды
входят в приоритет 1. Модели подключаются к движку Ocean через ProviderPort,
не через агентные CLI; локальные серверы выполняют вычисления на CPU/GPU.
См. [принятую архитектуру](platform-architecture.md) и
[план перехода](../superpowers/plans/2026-11-04-ocean-platform.md).
Разработка и приёмка идут на Linux-ноутбуке Omarchy. Stable 1.1 ещё не принят.

Ниже — исторический план и свидетельства Ocean 1.0, затем запись исходного
кандидата 1.1. Они не задают текущие ограничения на Desktop или общение ботов.
Рабочая копия выпуска 1.0 была `~/Projects/Ocean` на БигПК. Выполнены M0–M5 и RC;
Ocean 1.0 опубликован 2026-11-02. Наличие спецификации, тестов исходного Ocean или
демонстрации своего по отдельности недостаточно для приёмки 1.0.

## Кому и что поставляем

Владелец одного Linux-компьютера ведёт личные и групповые разговоры с ботами в локальном терминале. Профиль состоит из одного доверенного рабочего каталога и отдельной SQLite-базы. У базы один владелец-процесс. Комната, история и явная передача хода работают с реальным DeepSeek. Пакет можно установить в новый пользовательский каталог, проверить, обновить с резервной копией и восстановить после сбоя.

Первая квалифицируемая конфигурация — Linux x86_64 на БигПК, локальная файловая система, Node 26 (точный patch в манифесте кандидата), pnpm 12.16.1 для сборки. Производственная форма поставки — версионированный локально устанавливаемый архив CLI/TUI. Публичный npm, сетевой сервис, desktop, другие ОС, автоматические переговоры ботов и несколько пользователей не входят в критерии 1.0. Это проектные решения для первого выпуска, которые можно пересмотреть до заморозки кандидата. За квалификацию других целей отвечает отдельный цикл.

## Кандидат 1.1 RC2 (планируемый выпуск)

Дополнение для исходного кандидата stable от 2026-11-04: [read-only пилот GitHub](github-pilot.md)
прошёл реальную проверку через runtime/CLI/чат с явным согласием и точным грантом.
Исправлены привязка SDK-сессии к учётным данным и поколению, состояние после
перезапуска и скрытые повторы MCP. Это свидетельство исходного кандидата;
установленная GUI/TUI-приёмка, независимая проверка и решение о выпуске остаются
отдельными воротами. Запись RC2 ниже относится к его замороженному артефакту.

Стабильный выпуск 1.1 не объявлен: Ocean 1.0 остаётся опубликованной базой, а RC1 (`1.1.0-rc.1`) — установленным кандидатом. Ветка `codex/ocean-rc2` содержит следующий кандидат **RC2**: подключение провайдера через runtime, явную рассылку «Everyone» отдельно от заметки, настоящие изображения в запросах выбранной модели и пилотный read-only плагин GitHub с выключенным по умолчанию исполнением. Кандидат, его ограничения, происхождение свидетельств и незакрытые ворота зафиксированы в [записи RC2](rc-1.1.0-rc.2.md).

- **Реализовано в кандидате:** источники ключа `saved`/`external`/`injected` без секретов в профиле и копиях; явный disconnect перекрывает окружение после перезапуска; restore требует нового подключения; рассылка с замороженным составом и консервативным восстановлением; изображения с runtime-проверкой байтов, лимитами 4×10 МиБ / 34/47/48 МиБ / 8192 px и отказом для текстовой модели; схема 14→18 с откатом только восстановлением копии; исправление composer при 1024 px.
- **Входит в RC2:** Task 6 — плагинные инструменты через обычный чат (read-only GitHub пилот по точному гранту, durable journal, лимиты 16 вызовов/ход и 32 КиБ, явное подтверждение неопределённого исхода). Живой GitHub gate остаётся неквалифицированным без явно одобренного тестового подключения.
- **Не квалифицировано:** живой GitHub (исполнение плагинов выключено по умолчанию), живые особенности изображений DeepSeek, установленная приёмка GUI/RC2 на замороженной ревизии. Пропуски не считаются прохождениями.

Сборка и упаковка должны выполняться на точном Node v26.13.0 из манифеста. Archive содержит только продуктовые модули и публичную документацию: тестовые helper'ы (`*fixture*`, `*-cleanup*`) и внутренние `docs/superpowers/` в установленный продукт не попадают.

Приёмка RC2 — отдельный цикл: заморозка ревизии, независимая проверка, артефакты с точными хешами, одноразовые миграция/откат и установленная проверка, включая реальный GUI. Запись кандидата не заменяет решение владельца о выпуске 1.1.

## Кто отвечает

Разработчик реализует этап и фиксирует результат на конкретной ревизии. Проверяющий воспроизводит негативные и аварийные сценарии на временных данных. Оператор выполняет установку и восстановление на тестовом профиле. Владелец продукта принимает результат RC и разрешает фактический выпуск. На одном БигПК роли может выполнять один человек; в записи приёмки всё равно различают реализацию, результат проверки и решение выпустить.

Изменение формата данных, правил адресации, полномочий или матрицы поддерживаемых платформ сначала отражается в соответствующем контракте. Перед RC документацию сверяют с реальным help, версией базы и содержимым архива. Документы из `docs/integration/` описывают унаследованную базу.
