# Ocean 1.0. План до промышленного выпуска

Рабочая копия — `~/Projects/Ocean` на БигПК. Этот документ определяет целевой выпуск. Сейчас выполнены M0–M4. Наличие спецификации, тестов исходного Ocean или демонстрации своего по отдельности недостаточно для приёмки 1.0.

## Кому и что поставляем

Владелец одного Linux-компьютера ведёт личные и групповые разговоры с ботами в локальном терминале. Профиль состоит из одного доверенного рабочего каталога и отдельной SQLite-базы. У базы один владелец-процесс. Комната, история и явная передача хода работают с реальным DeepSeek. Пакет можно установить в новый пользовательский каталог, проверить, обновить с резервной копией и восстановить после сбоя.

Первая квалифицируемая конфигурация — Linux x86_64 на БигПК, локальная файловая система, Node 26 (точный patch в манифесте кандидата), pnpm 12.16.1 для сборки. Производственная форма поставки — версионированный локально устанавливаемый архив CLI/TUI. Публичный npm, сетевой сервис, desktop, другие ОС, автоматические переговоры ботов и несколько пользователей не входят в критерии 1.0. Это проектные решения для первого выпуска, которые можно пересмотреть до заморозки кандидата. За квалификацию других целей отвечает отдельный цикл.

## Последовательность работы

Каждый этап начинается после приёмки своих зависимостей. Разработчик предъявляет изменение, тест или воспроизводимую команду и результат. Номер шага задаёт порядок, а не календарное обещание.

| -------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| M0. Техническую последовательность M1–M4 дополняет [план функций и сценариев](v1.md). Контракт M1 реализован для памяти и SQLite. См. [реализованный API](../integration/conversations.md). ## Кто отвечает

Разработчик реализует этап и фиксирует результат на конкретной ревизии. Проверяющий воспроизводит негативные и аварийные сценарии на временных данных. Оператор выполняет установку и восстановление на тестовом профиле. Владелец продукта принимает результат RC и разрешает фактический выпуск. На одном БигПК роли может выполнять один человек; в записи приёмки всё равно различают реализацию, результат проверки и решение выпустить.

Изменение формата данных, правил адресации, полномочий или матрицы поддерживаемых платформ сначала отражается в соответствующем контракте. Перед RC документацию сверяют с реальным help, версией базы и содержимым архива. Документы из `docs/integration/` описывают унаследованную базу.
