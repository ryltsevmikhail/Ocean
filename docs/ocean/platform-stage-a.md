# Ocean Platform: проверка этапа A

Дата: 2026-11-04. Ревизия реализации: `1a99fcb`.
Этот документ описывает source/process проверки этапа A новой
[архитектуры платформы](platform-architecture.md), а не выпуск stable.
Этап A принят после независимых ревью A1, A2 и A3. Обязательных
исправлений в этих ревью не осталось; полное дерево и релиз ещё не приняты.

## Что проверено и изменено

Сохранён существующий application-цикл `runTurn`: модель → инструмент → модель.
Новый application-тест проверяет два запроса модели, один эффект, одну попытку,
передачу результата инструмента и ожидание записи claim до исполнения.
Неизвестный исход останавливает дальнейшие инструменты и запросы модели;
отказ разрешения не создаёт claim или эффект. Это проверка порядка через порт,
а не доказательство долговечности in-memory журнала.

Межпроцессные тесты используют настоящий owner, SQLite и независимые клиенты
на одноразовом профиле. У дочерних процессов пустой PATH; вызовы `codex` и
`claude` недоступны, Node запускается по абсолютному пути. Подтверждено:

- отключение первого клиента во время генерации не отменяет ход; второй видит
  прежний runId, один итоговый ответ и один вызов провайдера;
- разрыв после commit admission, до квитанции: повтор requestId возвращает
  исходную квитанцию, изменённые данные дают конфликт, модель не повторяется;
- SIGKILL после долговечного claim и фактического эффекта: после restart
  тот же эффект uncertain, повторов нет, отмена не считается подтверждённой;
- отдельный клиент со старым hello и замороженным валидатором RC2 работает
  с обычным чатом; неподдерживаемые операции не меняют полномочия.

Исправлена совместимость hello: необязательное `clientFeatures` содержит не более
16 строк длиной 1–64 символа. Текущий SDK объявляет
`plugin.session-authority-v1`. Старый клиент получает hello/status без plugin
capabilities, его plugin RPC отклоняются до dispatch с
`plugin_runtime_upgrade_required`. Проверки профиля, protocol, instance и
секретной capability сохранены. Текущий клиент по-прежнему отказывает старому
небезопасному plugin-owner. Объявление feature не выдаёт полномочий ботам.
Это совместимость wire-контракта RC2, не проверка установленного GUI.

Linux x86_64, Node 26.13.0, pnpm 12.16.1. Команды запускались из корня
`/home/ryltsevmg/Projects/Ocean-stable`, последовательно, в изолированных HOME,
XDG и TMPDIR без унаследованных credentials. В таблице не смешаны source и
process suites; root check останавливается до process-фазы на известном сбое.

Три прежних сбоя находятся в незакоммиченном

каталог и delayed refresh. Во всех наблюдается нежелательный `tools/list` после

обязательно переносится при замене Executor на этапе C; они не отключены.
Второй сохранённый файл — `apps/cli/test-fixtures/github-session-rig.ts`.
Оба оставлены без изменений и вне коммитов A, включая прежние format-ошибки.
Полное дерево не объявляется зелёным.

## Воспроизведение

На одноразовом профиле и с изолированным окружением:

```sh
pnpm test packages/application/src/own-engine.test.ts
pnpm test apps/cli/src/local-runtime/client-compatibility.test.ts packages/tools-node/src/local-plugin-compatibility.test.ts apps/cli/src/local-runtime/plugin-compatibility.test.ts apps/cli/src/local-runtime/lifecycle.test.ts
pnpm test:process apps/cli/src/local-runtime/own-engine-process.test.ts
pnpm test:process
pnpm check
pnpm build
pnpm format:check
```

Незавершённые изменения Executor не входят в коммиты A: приведённые числа и
baseline-сбои описывают именно сохранённое рабочее дерево, а не гарантированный
результат чистого checkout или другой ревизии. Для релиза F требуется
отдельная чистая ревизия и все обязательные exit 0.
