Реализуй RC2 по утверждённым приоритетам:

- P0: подключение DeepSeek из интерфейса — ключ, проверка, выбор модели, замена/отключение и настоящий статус.
- P0: отдельное «Всем» — по одному ответу от каждого участника, без автоматических переговоров ботов. Один пользовательский message, долговечные дочерние runId, дедупликация. Все отвечают на один замороженный контекст; ответы текущего пакета не подмешиваются остальным. «Заметка» остаётся без вызовов модели. Политика восстановления зафиксирована в spec.
- P0: настоящее понимание фотографий, схем и скриншотов через image input `deepseek-flash`. Передавать реальные проверенные байты через runtime и provider-neutral контракт. OCR не заменяет vision.
- P1: квалифицированный Executor и первый GitHub-плагин: каталог, подключения, права bot/room/repository, чтение issues в обычном чате. Комментарии, OAuth и второй сервис — следующая очередь. Без выделенного разрешённого тестового подключения не подменяй живую GitHub-приёмку локальной.
- P1: забрать готовые части Desktop-аудита 4–6; поле ввода на 1024 не должно перекрываться.
- Затем полный review `v1.0.0..RC2`, одна общая fix-волна, повторная приёмка, артефакты с SHA-256 и безопасное обновление установленного Ocean RC с сохранением ключа и переписки.

Используй superpowers:subagent-driven-development: один исполнитель за раз, независимое ревью задачи, продолжение по ledger. Workspace RC2 уже подготовлен в `.superpowers/sdd/2026-11-04-ocean-rc2`; в нём planning ledger и `rc1-review-carryover.md` с прежними решениями/отложенными замечаниями.
