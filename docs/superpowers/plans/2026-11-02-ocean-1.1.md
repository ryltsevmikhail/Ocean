# Ocean 1.1 Coding Tasks Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax. This document authorizes no implementation, deployment or credential enrollment by itself.

**Goal:** Dev edits project files and runs approved test presets; review evaluates the exact resulting changeset before owner-approved application.

**Architecture:** Keep domain pure, application in charge of task-scoped authority and durable effect admission, and adapters in charge of Git, sandbox, files and process supervision. Hosts present approvals and route explicit handoffs. Provider credentials remain in the host.

**Tech Stack:** TypeScript, Node 26, pnpm 12.16.1, SQLite schema 6, Linux x86_64, qualified bubblewrap/systemd user worker.

**Spec:** [Ocean 1.1](../../ocean/v1.1.md). Tasks 1–5 are implemented; see ../../integration/coding-tasks.md for its final interface. Tasks 6–7 remain planned.

## Global constraints

- Preserve 1.0 text-only behavior by default, public package boundaries, M4 replay/cancellation invariants and M5 restore restrictions.
- New/modified source files stay within 300 physical lines; split oversized responsibilities before adding behavior.
- No changes to installed 1.0 artifacts. No secret or real transcript fixtures. No automatic commit/push/merge/deploy by product agents.
- Namespace/cgroup prerequisites must be verified on BigPC; unsupported setup disables tool execution rather than weakening it.
- Source checkout must be clean at task creation and application; no automatic stash/reset.
- Every task includes failing regression → minimal implementation → green focused tests → commit. Final checks: pnpm check, pnpm build, pnpm format:check.

## Review focus

1. A second room/legacy entry point attempts to reuse an approval or mutate the same project: Task 1 and Task 4 admission tests.
2. Test code accesses a host key via HOME, proc, a symlink, pnpm dependency mount or user bus: Task 3 native canary tests.
3. A test process changes source or leaves a detached child after exit: Task 3 supervision and Task 6 stale-evidence tests.
4. New/untracked files or changed modes disappear from a Git diff: Task 2 snapshot completeness tests.
5. A crash or restore leaves an approval/application that appears reusable: Task 7 process fault and restoration tests.

## Execution order and definition of done

Implement Tasks 1–7 in order. Tasks 1–2 can ship as disabled internal capabilities; Task 3 is the prerequisite for any normal command execution. Task 5 is the first usable dev editing milestone; Task 6 completes the requested dev/review workflow; Task 7 is the release gate.

The feature is complete only when actual file changes, test exit/cleanup evidence and a review of their exact diff are visible through persistent CLI/TUI, refusals leave no unauthorized effect, and crash/restore never replays an unknown action. Document any qualification gap as open rather than reducing the boundary.
